# Contributing to FREEDAM DAO

> *"We hold these truths to be self-evident..."*
> FREEDAM is the infrastructure to mean it.

FREEDAM is a non-partisan, open-source DAO building permissionless infrastructure for civic governance. Every contribution — code, ideas, documentation, organizing, or simply spreading the word — moves the mission forward.

**You don't need permission to join a movement.**

---

## Ways to Contribute

### 1. Follow the Movement on X

Stay informed and help amplify the signal.

- Follow [@FREEDAMDAO](https://x.com/FREEDAMDAO)
- Like, repost, and share to grow the community
- Join the conversation around decentralized democracy

**Time:** 30 seconds. **Impact:** Compound.

### 2. Explore the Repo

The entire project lives in the open.

- Browse [github.com/FREEDAM-DAO/DAOv.01](https://github.com/FREEDAM-DAO/DAOv.01)
- Read the [Whitepaper](WHITEPAPER.md) to understand the full vision
- Review the [Constitution](CONSTITUTION.md) — the founding law of the DAO
- Check the [MVP Scope](MVP_SCOPE.md) for what's built and what's next
- Scan open issues for work that needs doing

**No technical skill required to start.** Curiosity is enough.

### 3. Visit the Website

See the mission in action.

- [freedamdao.org](https://www.freedamdao.org) — landing page with the current MVP phase overview
- Learn about soulbound membership, quadratic voting, and transparent governance
- Understand why FREEDAM exists and what makes it different

### 4. Volunteer as a Builder

FREEDAM needs builders of all kinds — code, governance, design, writing, community, legal, research.

- Fill out the [Volunteer Builder Application](https://docs.google.com/forms/d/e/1FAIpQLScyCh872PXzc6pIMslrf3JBK7I7eTdBwM28fLE6URCz8ygbKQ/viewform)
- Tell us your skills and how much time you can commit
- We match contributors to working groups based on interest and availability

**All skill levels welcome.** Enthusiasm counts more than experience.

## Contribution Guidelines

### For Code Contributions

1. Fork the repo and create a branch from `main`
2. Follow the existing code style and conventions
3. Write or update tests for any new functionality
4. Ensure all tests pass before submitting
5. Open a pull request with a clear description of what it does and why

### For Documentation & Governance

1. Propose changes as a GitHub issue or pull request
2. Substantive governance changes follow the proposal lifecycle in the Constitution
3. Small fixes (typos, broken links, formatting) can go directly to PR

### For Community & Design

1. Join a working group through the volunteer form
2. Coordinate with the group lead on priorities
3. Share work-in-progress early for feedback
